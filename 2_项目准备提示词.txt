================================================================
  【本 Skill 来自 NIO嘉亮加仑】
  项目准备提示词 · 从零搭好 MG 动画环境
  用法：把下面整段（从 <role> 到 </report>）复制给你的 AI Agent
  适用：一台干净电脑，只有 Agent 和模型，其他依赖都没有
================================================================

注意：这份提示词只适用于能执行命令、读写本地文件的 Agent。
如果你只是网页聊天机器人，先告诉用户，不要假装安装。

【运行时兼容】
- Claude Code / WorkBuddy / DeepSeek Harness 三端通用。
- <SKILL_DIR> = 本文件所在目录；<WORKDIR> = 用户指定的工作目录。
- 能执行命令的 Agent：按步骤实际执行、实际验证。
- 不能执行命令的 Agent：只输出命令清单和验证方法，让用户自己跑；
  不要假装已经装好。
- DSH 默认只能写会话工作区：如果写 <WORKDIR> 被拒，先让用户授权，
  或把会话工作区设到 <WORKDIR>。
- WorkBuddy 默认工作区在 `_sessions`：做片前把工作区切到项目目录。
- PowerShell 5.1（DSH / Windows）输出中文前先设：
  [Console]::OutputEncoding = [System.Text.Encoding]::UTF8
  写文件用 UTF-8 无 BOM。

<role>
你是环境搭建工程师 + 视频工具链工程师。
你的任务不是做片，而是把一台干净电脑搭到「能稳定渲染 MG 动画」的状态，
并完成一次 10 秒端到端测试渲染。每一步都要实际执行、实际验证，不许凭印象说“应该可以”。
</role>

<goal>
在一台干净电脑上，从零安装并验证以下链路：

  Node.js 22+
  → HyperFrames CLI
  → FFmpeg / FFprobe（全量版）
  → 无头 Chrome
  → AI 技能包（让 Agent 会写 HyperFrames 页面）
  → 本地 GSAP + 本地中文字体
  → 一个 10 秒测试项目
  → 一条能播放的 H.264 MP4

最终交付：
1. 一条 10 秒测试片（out/smoke.mp4），ffprobe 能看到正确时长/分辨率/编码。
2. 一份 <WORKDIR>/环境说明.md，写清每个组件的版本、路径、验证命令。
3. 一份 <WORKDIR>/启动环境 脚本（Windows 用 .ps1，macOS/Linux 用 .sh）。
</goal>

<workdir>
默认工作目录：
- Windows：D:\AIVIDEO
- macOS / Linux：~/AIVIDEO

如果用户指定了别的目录，以用户为准。
所有项目、缓存、工具、字体都放在 <WORKDIR> 下，不要散落到系统目录。
在 <WORKDIR> 下建：
  projects/     放具体视频项目
  tools/        放手动下载的 ffmpeg 等工具（如果需要）
  cache/        放渲染缓存、模型缓存
  assets/       放跨项目共用的字体、音效、图片
</workdir>

<constraints>
1. 先探测，再安装。已经存在且版本达标的组件，不要重复安装。
2. 每一步装完立刻验证；验证失败就停下来报告，不要连续猜。
3. 不下载破解软件、来源不明的二进制、付费素材。
4. 字体和 JS 库下载后必须本地化；渲染时不允许依赖 CDN。
5. 不替用户决定视频风格；本阶段只搭环境 + 测试片。
6. 不删除用户已有文件；新增文件限制在 <WORKDIR> 和包管理器范围内。
7. 所有命令都要能在当前 shell 里复现；不要只说“你去装一下”。
8. 如果命令需要管理员权限、重启、或长时间下载，先告诉用户再执行。
9. 如果网络被墙或 npm/pip 很慢，先问用户是否有代理；不要默默卡住。
10. 只有 ffprobe 能看到成品文件，才算渲染成功。退出码 0 不算。
</constraints>

<steps>

第 0 步 · 探测系统
----------------------------------------------------------------
先打印并记录：
- 操作系统与版本、CPU 架构
- 可用磁盘空间（至少留 10GB）
- 是否已有：node、npm、ffmpeg、ffprobe、git、python
- 可用的包管理器：Windows 的 winget / choco / scoop；
  macOS 的 brew；Linux 的 apt / dnf / pacman

参考命令：
  Windows PowerShell：
    Get-ComputerInfo | Select-Object OsName, OsVersion, CsTotalPhysicalMemory
    node -v; npm -v; ffmpeg -version; ffprobe -version; git --version; python --version
    Get-Command winget, choco, scoop -ErrorAction SilentlyContinue
  macOS / Linux：
    uname -a; df -h .
    node -v; npm -v; ffmpeg -version; ffprobe -version; git --version; python3 --version

把探测结果先回报给用户，再继续。

第 1 步 · 建工作目录
----------------------------------------------------------------
创建 <WORKDIR> 及 projects/、tools/、cache/、assets/ 四个子目录。
把 <SKILL_DIR> 里的 3_项目唤醒词.txt、4_任务卡.txt、5_常见坑速查.txt
复制到 <WORKDIR> 根目录，方便以后唤醒时读取。
如果 Agent 不能写 <WORKDIR>（DSH 默认只写会话工作区，WorkBuddy 默认在 _sessions），
先让用户授权，或把会话工作区切到 <WORKDIR>，不要写到别的盘。

第 2 步 · 安装 Node.js 22+
----------------------------------------------------------------
HyperFrames 要求 Node.js 22 或更高。

Windows：
  winget install --id OpenJS.NodeJS.LTS -e --accept-source-agreements --accept-package-agreements
  如果没有 winget：从 https://nodejs.org/en/download 下载 LTS 的 .msi 安装包，
  用 msiexec /i <安装包> /qn 静默安装。

macOS：
  brew install node
  或从 https://nodejs.org/en/download 下载 .pkg。

Linux：
  curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
  sudo apt-get install -y nodejs
  （Fedora 用 dnf，Arch 用 pacman，按发行版调整。）

验证：
  node -v     # 主版本必须 >= 22
  npm -v
如果当前 shell 找不到 node，重开终端；仍找不到就把 Node 的 bin 目录加进 PATH。

第 3 步 · 安装 FFmpeg / FFprobe（全量版）
----------------------------------------------------------------
必须用全量构建，不能用来路不明的精简版（可能缺 libx264、setparams 等）。

Windows：
  winget install --id Gyan.FFmpeg -e --accept-source-agreements --accept-package-agreements
macOS：
  brew install ffmpeg
Linux：
  sudo apt-get install -y ffmpeg

验证：
  ffmpeg -version
  ffprobe -version
  ffmpeg -hide_banner -bsfs | grep setparams
  ffmpeg -hide_banner -encoders | grep libx264
Windows 没有 grep 时用 findstr：
  ffmpeg -hide_banner -bsfs | findstr setparams
  ffmpeg -hide_banner -encoders | findstr libx264

如果包管理器装的是精简版、或验证失败：
  Windows 从 https://www.gyan.dev/ffmpeg/builds/ 下载 full build；
  macOS 从 https://evermeet.cx/ffmpeg/ 下载；
  解压到 <WORKDIR>/tools/ffmpeg，并把 bin 目录加进 PATH。
  然后设置：
    HYPERFRAMES_FFMPEG_PATH=<绝对路径>/ffmpeg(.exe)
    HYPERFRAMES_FFPROBE_PATH=<绝对路径>/ffprobe(.exe)

第 4 步 · 安装 HyperFrames CLI
----------------------------------------------------------------
推荐全局安装，避免每次 npx 重新下载：
  npm install -g hyperframes@latest
  hyperframes --version

如果全局安装报权限错误（macOS/Linux 常见）：
  不要用 sudo npm install -g；
  改用 npx：
    npx --yes hyperframes@latest --version
  后续所有命令都用 `npx hyperframes ...` 代替 `hyperframes ...`。

第 5 步 · 下载渲染用 Chrome
----------------------------------------------------------------
  npx hyperframes browser ensure
  npx hyperframes browser path

如果 CLI 提示登录、套餐或额度：先按官网提示处理。
本包只用本地渲染，不需要云渲染；本地渲染通常不消耗云额度。

HyperFrames 使用固定版本的 Chrome Headless Shell，保证不同机器渲染结果一致。
如果下载失败：
  - 检查代理 / 防火墙；
  - 设置 HTTPS_PROXY / HTTP_PROXY 后重试；
  - 仍失败就报告具体错误，不要用系统 Chrome 顶替。

第 6 步 · 环境自检
----------------------------------------------------------------
  npx hyperframes doctor --json

判读：
- Node.js / FFmpeg / FFprobe / Chrome 必须都 ok。
- Docker / Docker running 显示 fail 是正常的，本地渲染不需要 Docker。
- 如果顶层 ok 为 false，逐项看 checks，先修 Node / FFmpeg / Chrome。
- 如果 doctor 因为可选工具（本地 TTS、Docker 等）失败，不影响核心渲染，
  在报告里说明即可。

只有核心四项全绿，才进入下一步。

第 7 步 · 安装 AI 技能包
----------------------------------------------------------------
这一步让 Agent 学会 HyperFrames 的页面契约、命令和检查规则：
  npx hyperframes skills update
  npx hyperframes skills check

它会安装核心技能：
  /hyperframes
  /hyperframes-cli
  /hyperframes-registry
  /media-use

如果 `skills check` 提示核心技能缺失，再运行一次：
  npx hyperframes skills
装完提醒用户：重启一次 Agent 会话，新技能才会被加载。
如果网络受限，也可以稍后再装；但做片前必须装好。
无论你用 Claude Code、WorkBuddy 还是 DeepSeek Harness，
技能包装不上都不影响核心渲染：
用 `npx hyperframes docs <topic>` 查页面契约即可。

WorkBuddy / DSH 如果装不上 HyperFrames 技能包，让 Agent 先读这三份本地文档：
  npx hyperframes docs data-attributes
  npx hyperframes docs gsap
  npx hyperframes docs compositions

第 8 步 · 建测试项目
----------------------------------------------------------------
  cd <WORKDIR>/projects
  npx hyperframes init smoke-test --resolution landscape --non-interactive
  cd smoke-test

`init` 会生成一个可运行的空项目，并安装核心技能。
先不要改任何东西，直接跑一次：
  npx hyperframes check --json
  npx hyperframes render --quality draft --output out/blank.mp4
  ffprobe -v error -show_entries format=duration:stream=codec_name,width,height \
    -of default=noprint_wrappers=1 out/blank.mp4

如果能出片，说明 Node → Chrome → FFmpeg 整条链路通了。
如果 blank 都渲不出来，先修链路，不要继续写自定义页面。

第 9 步 · 本地化 GSAP 和字体
----------------------------------------------------------------
在 smoke-test 目录：
  npm install gsap @fontsource/noto-sans-sc @fontsource/noto-serif-sc

把 GSAP 复制到项目里：
  mkdir -p assets/vendor assets/fonts
  macOS/Linux：
    cp node_modules/gsap/dist/gsap.min.js assets/vendor/
  Windows PowerShell：
    Copy-Item node_modules/gsap/dist/gsap.min.js assets/vendor/

把中文字体复制到 assets/fonts：
  macOS/Linux：
    find node_modules/@fontsource/noto-sans-sc/files -name "*.woff2"
    find node_modules/@fontsource/noto-serif-sc/files -name "*.woff2"
  Windows PowerShell：
    Get-ChildItem node_modules/@fontsource/noto-sans-sc/files -Filter *.woff2

注意：@fontsource 会按字符集拆成多个文件，例如 latin / chinese-simplified。
中文必须选文件名里带 chinese-simplified 的，不要只复制 latin，
否则中文还是方块。

挑 400 / 700 / 900 三个字重，复制到 assets/fonts/，
文件名改成简单、无空格的名字，例如：
  noto-sans-sc-400.woff2
  noto-sans-sc-700.woff2
  noto-sans-sc-900.woff2

然后在页面里用 @font-face 引用。不要用 Google Fonts 的在线 CSS，
也不要在渲染时联网取字体。

第 10 步 · 写一个 10 秒测试页
----------------------------------------------------------------
先把原始 index.html 备份成 index.blank.html，再写测试页。
在 smoke-test/index.html 写一个最小测试页，必须遵守 HyperFrames 契约：

- 根节点：
    data-composition-id="main"
    data-start="0"
    data-duration="10"
    data-fps="30"
    data-width="1920"
    data-height="1080"
- 每个有时间范围的元素：
    class="clip"
    data-start="秒"
    data-duration="秒"
- 一条 paused 的 GSAP 主时间轴，注册到：
    window.__timelines["main"]
- 只用本地 assets/vendor/gsap.min.js 和 assets/fonts/ 里的字体。
- 动画只能是时间的函数：
    禁止 Date.now()、Math.random()、setTimeout、网络请求、repeat: -1。
- 中文字必须用 @font-face 的本地字体，确保不是方块。

测试内容建议（中性、不带任何品牌风格）：
  0–3 秒：标题从下方淡入，一条线从左向右展开
  3–6 秒：切到第二屏，标题换字
  6–10 秒：第三屏，一个进度条从 0 走到 100%
全部用纯色块和文字，不要用外部图片。

参考骨架：
----------------------------------------------------------------
<!doctype html>

<head>
<meta charset="utf-8">
<script src="assets/vendor/gsap.min.js"></script>
<style>
  @font-face {

    font-weight: 400;
  }
  @font-face {
    font-family: "Noto Sans SC";
    src: url("assets/fonts/noto-sans-sc-700.woff2") format("woff2");
    font-weight: 700;
  }
  * { margin: 0; padding: 0; box-sizing: border-box; }
  html, body { width: 1920px; height: 1080px; overflow: hidden; background: #ffffff; }
  #root {
    position: relative; width: 100%; height: 100%;
    font-family: "Noto Sans SC", sans-serif; color: #111111;
  }
  .clip { position: absolute; }
  .scene { position: absolute; inset: 0; }
  h1 { font-size: 96px; font-weight: 700; }
  .bar-track {
    position: absolute; left: 160px; top: 560px;
    width: 800px; height: 24px; background: #e5e7eb;
  }

    width: 100%; height: 100%; background: #1d4ed8;
    transform-origin: left center; transform: scaleX(0);
  }
</style>
</head>
<body>
<div id="root"
     data-composition-id="main"
     data-start="0" data-duration="10" data-fps="30"
     data-width="1920" data-height="1080">

  <div class="scene clip" data-start="0" data-duration="3">
    <h1 id="t1" style="position:absolute;left:160px;top:420px;">MG 动画测试</h1>
    <div class="bar-track">
      <div class="bar-fill" id="b1"></div>
    </div>
  </div>

  <div class="scene clip" data-start="3" data-duration="3">
    <h1 id="t2" style="position:absolute;left:160px;top:420px;">第二屏</h1>
  </div>

  <div class="scene clip" data-start="6" data-duration="4">
    <h1 id="t3" style="position:absolute;left:160px;top:420px;">进度到 100%</h1>

      <div class="bar-fill" id="b3"></div>
    </div>
  </div>

<script>
  const tl = gsap.timeline({ paused: true });

  tl.from("#t1", { y: 60, opacity: 0, duration: 0.6, ease: "power3.out" }, 0);
  tl.to("#b1", { scaleX: 1, duration: 1.2, ease: "power2.out" }, 0.6);

  tl.from("#t2", { y: 60, opacity: 0, duration: 0.6, ease: "power3.out" }, 3);

  tl.from("#t3", { y: 60, opacity: 0, duration: 0.6, ease: "power3.out" }, 6);
  tl.to("#b3", { scaleX: 1, duration: 2.0, ease: "power2.out" }, 6.5);

注意：上面的字体文件名必须和你实际复制进去的文件名一致；
不一致就改 @font-face 的 url，不要留一个不存在的路径。

第 11 步 · 检查、抽帧、试渲
----------------------------------------------------------------
  npx hyperframes check --json

- 必须 0 error；warning 逐条看，能修就修。
- 报错一般带 `Fix:` 行，按它修。

  npx hyperframes snapshot --at 0.5,2,5,8

打开生成的 PNG 逐张看：
- 中文是不是方块？
- 三屏内容是不是按时间出现？
- 有没有元素出框、重叠、太小？
- 有没有空白帧？
如果你的模型不能看图，就把 PNG 路径给用户，让用户确认。

然后渲染 10 秒测试片：
  npx hyperframes render --quality draft --output out/smoke.mp4

用 ffprobe 验收：
  ffprobe -v error \
    -show_entries format=duration:stream=codec_name,width,height \
    -of default=noprint_wrappers=1 out/smoke.mp4

期望：
- duration 约 10 秒
- codec_name = h264
- width = 1920，height = 1080
- 文件大小非 0

再抽几帧看成品（用 ffmpeg，最稳）：
  ffmpeg -y -i out/smoke.mp4 -ss 1 -frames:v 1 out/frame-1.png
  ffmpeg -y -i out/smoke.mp4 -ss 4 -frames:v 1 out/frame-4.png
  ffmpeg -y -i out/smoke.mp4 -ss 8 -frames:v 1 out/frame-8.png

再写启动脚本：

第 13 步 · 可选：音频模块（用户明确要做旁白/配乐时再做）
----------------------------------------------------------------
如果用户没提音频，跳过这一步，先交付无声测试片。

先装 Python（只有音频模块需要）：
  Windows：winget install --id Python.Python.3.12 -e
           如果 `python` 打开的是应用商店，用 `py -3` 或装完重开终端。
  macOS：  brew install python@3.12
  Linux：  sudo apt-get install -y python3 python3-pip python3-venv
验证：
  python --version   # 或 python3 --version

中文配音有三条路，先让用户选，不要默认：
A. HyperFrames 自带 Kokoro（本地）
   - 需要 Python 3.10+：
       python -m pip install kokoro-onnx soundfile
   - 中文音素需要 espeak-ng：
       Windows: winget install eSpeak-NG.eSpeak-NG
       macOS:   brew install espeak-ng
       Linux:   sudo apt-get install -y espeak-ng
   - 先列声音：
       npx hyperframes tts --list
   - 选一个 z 开头的中文声音，合成 3 句样音试听：
       npx hyperframes tts "这是一句中文测试。" --voice <z开头的声音> --lang zh -o test.wav
   - 如果发音乱、吞字、像机器人，换 B 或 C，不要硬用。

B. edge-tts（免费在线，轻量）
   - python -m pip install edge-tts
   - edge-tts --list-voices | grep zh-CN
   - edge-tts --voice zh-CN-XiaoxiaoNeural \
       --text "这是一句中文测试。" --write-media test.mp3
   - 注意：会把文本发到微软在线服务；隐私内容不要用。

C. 用户自己的本地 TTS
   - 按用户指定的工具安装；先合 3 句样音，确认音色和语速再写全稿。

词级对齐（做逐字字幕/卡点时才需要）：
  npx hyperframes transcribe voice.wav --model small --language zh
注意：必须显式指定 --model 和 --language，
默认模型 small.en 会把中文悄悄翻译成英文。

BGM：
- 优先用用户提供的、可商用的音乐文件。
- 也可以用 HyperFrames 的 media-use 找免费音乐：
    npx hyperframes media-use resolve --type bgm --intent "<情绪/风格/节奏>" --project .
- 不要用来路不明的商业歌曲做公开视频。

混音（先渲无声 MP4，再混音，最好排查）：
  ffmpeg -y -i out/smoke.mp4 -i voice.wav -stream_loop -1 -i bgm.wav \
    -filter_complex "[1:a]volume=2.0[a1];[2:a]volume=0.25[a2];[a1][a2]amix=inputs=2:duration=longest[a]" \
    -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -shortest out/final.mp4

说明：
- volume=2.0 是补偿 amix 默认把每个输入减半；觉得人声太冲就降到 1.6。
- 老版本 FFmpeg 的 amix 没有 normalize 参数，别写。
- 混完再用 ffprobe 看有没有音轨。

</steps>

<failure-playbook>
常见失败与处理：
- node: command not found
  → 重开终端；仍不行就把 Node 的安装目录加进 PATH。
- Node 版本低于 22
  → 升级到 LTS 22+，不要用旧版本硬跑。
- ffmpeg: command not found
  → 安装 FFmpeg，或设置 HYPERFRAMES_FFMPEG_PATH。
- No such filter: 'setparams'
  → 用了精简版 FFmpeg；换全量构建。
- Chrome 红 / 启动超时
  → npx hyperframes browser ensure；检查代理；不要用系统 Chrome 顶替。
- npx 每次都很慢
  → 改成全局安装 npm install -g hyperframes@latest。
- npm 下载卡住
  → 问用户是否有代理；国内可临时用 registry.npmmirror.com。
- pip 下载卡住
  → 问用户是否有代理；国内可临时用阿里云 PyPI 镜像。
- check 报错
  → 读 `Fix:` 行；先修 error，再看 warning。
- 渲染内存爆 / 卡死
  → 降低 worker 数，或用 draft 画质；一次只跑一个整片。
- 渲染退出码 0 但没有文件
  → 九成是 FFmpeg 不在 PATH；检查 PATH 和 HYPERFRAMES_FFMPEG_PATH。
- 中文显示方块
  → @font-face 没加载；检查字体路径和文件名。
- 每帧画面不一样
  → 动画里用了 Date.now / Math.random / 无限循环，删掉。
- 成品没有声音
  → 先确认页面里有没有 audio；更稳的是渲无声再 ffmpeg 混音。
- 音画不同步
  → BGM 用 -stream_loop -1，最后 -shortest 收口；不要手动猜时长。
- snapshot 全黑
  → 字体/图片没加载完，或时间轴没注册；检查 window.__timelines。
- 权限不足（全局 npm）
  → 不要 sudo；改用 npx，或配置 npm prefix。
</failure-playbook>
