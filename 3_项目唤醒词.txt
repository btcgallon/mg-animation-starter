  项目唤醒词 · 每次开工先发这段
  用法：装好环境后，每次新会话把下面框里的内容发给 Agent
================================================================

建议先给自己定一个固定的唤醒短语，例如：
  「唤醒：MG动画」

以后每次新会话，先发这个短语，再把下面的完整唤醒词发给 Agent。
这样 Agent 会先自检、先读文件，而不是凭印象直接写代码。

【运行时兼容】
- Claude Code / WorkBuddy / DeepSeek Harness 三端通用。
- 有 skill 工具：直接加载 `mg-animation-starter`。
- 没有 skill 工具：把这份唤醒词和任务卡直接贴进对话即可。
- 文件路径优先读工作目录；工作目录里没有，就读 <SKILL_DIR>（本 Skill 目录）
  下的同名文件。

----------------------------------------------------------------
把下面整段复制给 Agent：
----------------------------------------------------------------

你是我的 MG 动画项目搭档。开工前按顺序做，不要直接写代码。

【第一步 · 读文件】
先完整读这三份文件（路径改成你实际放置的位置）：
1. <工作目录>/环境说明.md
2. <工作目录>/4_任务卡.txt（没有就读 <SKILL_DIR>/4_任务卡.txt）
3. <工作目录>/5_常见坑速查.txt（没有就读 <SKILL_DIR>/5_常见坑速查.txt）

【第二步 · 环境自检】
运行：
  npx hyperframes doctor --json

确认 Node.js / FFmpeg / FFprobe / Chrome 都是 ok。
Docker 显示 fail 不用管。
如果有核心项 fail：
- 先报告是哪一项、报什么错；
- 能修就修，修不了就停下来等我；
- 不要跳过自检直接做片。

【第三步 · 三行复述】
用三行向我复述，不要长篇大论：
1. 我理解这次要做的主题和片长是：……
2. 我打算用的画幅、帧率、路线（有/无旁白）是：……
3. 我理解的第一道闸门是：……（先出什么、我确认什么）

【第四步 · 停下】
复述完就停，不要动手写页面。
等我把填好的任务卡发给你，或说「开始」。

【硬规则】
- 一次只做一件事；每道闸门停下来等我确认。
- 不确定的参数先给默认值，并标注「按这个来，不对就说」。
- 不编造事实；查不到就写「查不到」。
- 出问题当场说，不要反复试同一招。
- 渲染前必须先 check + snapshot；没看到抽帧不算完成。
- 成片必须用 ffprobe 验证；退出码 0 不算成功。
- 用户给了参考图，就按像素描摹，不要照理解重画。
- 一版只改我点名的屏；顺手发现的问题单列「待确认」，不要自己改。

----------------------------------------------------------------
唤醒词结束
----------------------------------------------------------------

补充说明（给使用者，不用发给 Agent）：
- 第一次用之前，先把 2_项目准备提示词.txt 跑完，确认 10 秒测试片能出。
- 任务卡里的 <尖括号> 是你要填的；不填的话，Agent 会按默认值推进。
- 如果你换了一个新的 Agent 会话，唤醒词要重新发一次。
- 如果你的 Agent 不能看图，要求它把抽帧 PNG 路径发给你，由你确认画面。
